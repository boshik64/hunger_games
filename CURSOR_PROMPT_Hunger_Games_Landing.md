## 0. Роль и правила работы

Ты — senior frontend-инженер (React/TypeScript, мобильные веб-игры, Canvas, Web Share API). Нужно построить промолендинг-мини-RPG для сети кинотеатров КАРО к премьере фильма. Бриф ниже основан на утверждённом ТЗ для ИТ. **ТЗ — закон**: тексты, порядок экранов, таблица результатов, события аналитики, критерии готовности нельзя менять и «улучшать». Если что-то в ТЗ неоднозначно — выбери самый простой вариант, зафиксируй его в `docs/DECISIONS.md` одной строкой и иди дальше, не задавая вопросов.

Жёсткие правила:
1. **Весь видимый текст — только из `src/content/ru.ts`**, дословно как в разделе 6. Никаких текстов в JSX.
2. **Все визуальные материалы — через манифест ассетов** (раздел 9). Финальные слои от дистрибьютора придут позже, поэтому сейчас везде плейсхолдеры, а замена должна сводиться к подмене файлов + правке одного манифеста, без правок компонентов.
3. **Не использовать официальные логотипы, постеры, шрифты и кадры «Голодных игр»** — только нейтральные плейсхолдеры, сгенерированные скриптом.
4. Без бэкенда, без регистрации, без cookies-авторизации. Статический билд.
5. Игра полностью работает без анимаций и без звука. Звука нет вообще.
6. Мобильный приоритет (mobile-first), затем десктоп.

## 2. Стек и инфраструктура

- **Vite + React 18 + TypeScript (strict)**. Без Next.js (нужен статический билд).
- Состояние: **Zustand** + `persist` в **`sessionStorage`** (не localStorage — по ТЗ состояние живёт «в пределах сессии браузера»).
- Стили: **CSS Modules + CSS custom properties** (дизайн-токены в `src/styles/tokens.css`). Tailwind не использовать.
- Анимации: CSS (transform/opacity) + при необходимости `motion` (Framer Motion). Только `transform` и `opacity`, без анимации layout-свойств. Обязательно учитывать `prefers-reduced-motion: reduce` (анимации заменяются на мгновенные смены/кроссфейд ≤150 мс).
- Шрифты: **self-hosted WOFF2 с кириллицей** (плейсхолдеры: *Oswald* для заголовков, *Inter* для текста; обе OFL). Никаких Google Fonts CDN — нужна стабильность и нужные шрифты внутри Canvas. Финальный шрифт тоже придёт позже → токен `--font-display`/`--font-body` + `src/assets/fonts.ts`.
- Тесты: **Vitest** (логика) + **Playwright** (e2e, мобильные эмуляции WebKit/Chromium).
- Линт: ESLint + Prettier. `tsc --noEmit` в CI-скрипте.
- Переменные окружения (`.env.example`):
  ```

  VITE_ANALYTICS_ID=                                   # данные подключения аналитики КАРО
  ```

- Скрипты: `dev`, `build`, `preview`, `test`, `e2e`, `gen:placeholders`, `check:assets`.

## 4. Пользовательский путь и конечный автомат

Четыре экрана строго по порядку: **draw → item → strategy → result**. Принимается два игровых решения. Прохождение без регистрации, ≈1 минута (максимум 3). Таймера и принудительного завершения нет. Проигрыша, шкал ресурсов и доп. заданий нет. **Все проходят испытание**; результат — стиль выживания. Дистрикт влияет только на визуальную персонализацию (символ, цветовой акцент, подпись), но **не на результат**.

### 4.1 Состояние (`game/types.ts`)

```ts
type Screen = 'draw' | 'item' | 'strategy' | 'result';
type ItemId = 'flask' | 'rope' | 'medkit';
type StrategyId = 'risk' | 'careful';
type CharacteristicId = 'strategist' | 'daredevil' | 'tactician' | 'survivor';

interface GameState {
  screen: Screen;
  district: number | null;          // 1..12, сохраняется на всю сессию, включая повторные попытки
  drawn: boolean;                   // жребий уже раскрыт (анимация завершена)
  isDrawing: boolean;               // идёт анимация жеребьёвки (НЕ персистится)
  item: ItemId | null;              // ПОДТВЕРЖДЁННЫЙ предмет
  strategy: StrategyId | null;      // ПОДТВЕРЖДЁННАЯ стратегия
  pendingItem: ItemId | null;       // выделенная, но не подтверждённая карточка (UI-состояние)
  pendingStrategy: StrategyId | null;
  isTransitioning: boolean;         // блокировка повторных нажатий на время перехода (НЕ персистится)
  attempt: number;                  // 1, 2, 3… в рамках сессии
  completedAttempts: number[];      // для дедупликации game_completed
  activeTimeMs: number;             // накопленное активное время текущей попытки
  sessionId: string;
}
```

### 4.2 Переходы (единственные допустимые)

| Из | Действие | В | Побочные эффекты |
|---|---|---|---|
| draw (не вытянут) | «Вытянуть жребий» | draw (анимация) | `isDrawing=true`; **district выбирается сразу** (равновероятно 1..12) и пишется в стор; `draw_start`, `district_assigned` (один раз). По окончании анимации `drawn=true`, `isDrawing=false` |
| draw (вытянут) | «Подготовиться» | item | — |
| draw (любое) | «Выбрать сеанс» | внешняя ссылка | `ticket_cta_click {screen:'draw'}` |
| item | клик по карточке | item | только `pendingItem` (можно менять сколько угодно) |
| item | «Продолжить» (активна только при `pendingItem`) | strategy | `item=pendingItem`, `item_selected` |
| strategy | клик по карточке | strategy | только `pendingStrategy` |
| strategy | «Узнать свою судьбу» (активна только при `pendingStrategy`) | result | `strategy=pendingStrategy`, результат вычисляется по таблице, `strategy_selected`, затем `game_completed` (один раз на попытку) |
| result | «Выбрать сеанс» | внешняя ссылка | `ticket_cta_click {screen:'result'}` |
| result | «Поделиться результатом» | — | см. раздел 8 |
| result | «Скачать карточку» | — | см. раздел 8 |
| result | «Пройти ещё раз» | item | `replay_click`; `attempt++`; сброс `item`, `strategy`, `pending*`, результата, `activeTimeMs`; **district сохраняется** |

Общие правила:
- Клик по карточке **никогда** не переключает экран — только кнопка подтверждения.
- Пока `isTransitioning || isDrawing` — все интерактивные элементы экрана получают `aria-disabled`, обработчики игнорируют события (guard в сторе, а не только в UI). Повторные нажатия не создают действий и событий.
- Выбранная карточка отличается не только цветом: **галочка/отметка выбора в углу + рамка + `aria-checked=true`**.
- Всё доступно обычным тапом. Никаких long-press/drag/hover-only.
- Текст показывается сразу, **без посимвольного набора**.
- Постоянно виден прогресс (4 шага) и дистрикт (бейдж с номером и символом) — как только дистрикт назначен.
- На экране стратегии ранее выбранный предмет виден как напоминание (мини-чип с иконкой и названием).

### 4.3 Восстановление после обновления страницы

Персистим в `sessionStorage` (ключ `kg:v1`): `screen, district, drawn, item, strategy, attempt, completedAttempts, activeTimeMs, sessionId`. Не персистим: `isDrawing`, `isTransitioning`, `pending*` (по желанию можно сохранять и их — выбери проще и запиши в DECISIONS).
- Если страница перезагружена посреди анимации жеребьёвки — district уже в сторе, поэтому восстанавливаем сразу в раскрытое состояние (`drawn=true`) **без повторных событий аналитики**.
- Если `screen==='result'`, но нет `item` или `strategy` (битое состояние) — откатываем на `item`.
- Версионирование ключа; при несовместимой схеме — тихий сброс.
- Новая сессия браузера → начинается с жеребьёвки.
- Восстановление показанного экрана **не** шлёт `game_completed`, `item_selected` и т.д. (см. раздел 10).

### 4.4 Случайность

`game/random.ts`: `drawDistrict()` — равновероятно 1..12, через `crypto.getRandomValues` с rejection sampling (без modulo bias), фолбэк на `Math.random`. Юнит-тест: 120 000 вызовов, каждый дистрикт в пределах ±3% от ожидания; все 12 достижимы. Для тестов — инъекция RNG.

## 7. Экраны: поведение и вёрстка

### Общее
- Один экран = одна «сцена» (слои фона + контент). Высота `100dvh`, учёт `env(safe-area-inset-*)`. Контент вертикально по центру/низу, главная кнопка всегда видна в нижней трети экрана без скролла на 360×640. На маленьких экранах допустим внутренний скролл контента, но кнопка подтверждения — `position: sticky` внизу.
- Тап-зоны ≥ 48×48 px. Контраст текста ≥ 4.5:1 (проверять поверх плейсхолдерных фонов, подложки/градиенты под текстом).
- При смене экрана: фокус переносится на `h1` экрана (`tabIndex=-1`), `aria-live="polite"` объявляет смену шага.
- Карточки выбора — `role="radiogroup"` / `role="radio"`, стрелки клавиатуры, `Space/Enter` выбирают.
- Кнопка «Выбрать сеанс» визуально приоритетна на результате (primary, самая яркая). На первом экране — secondary рядом с «Вытянуть жребий» (который там primary).

### Экран 1 — жеребьёвка
- До жребия: заголовок, подзаголовок, подпись, две кнопки.
- Анимация (≈1.5–2.0 с, **не дольше 2.5 с**): «перемешивание» — быстро сменяющиеся номера/свитки/шары, затем «раскрытие жребия». На время анимации «Вытянуть жребий» блокируется; «Выбрать сеанс» остаётся доступной.
- После: номер дистрикта (крупно), символ (плейсхолдер), короткая характеристика, бейдж закрепляется в шапке прогресса. Кнопка → «Подготовиться».
- `prefers-reduced-motion`: без перемешивания, мгновенное раскрытие.

### Экран 2 — предмет
- Три карточки (иконка-плейсхолдер + название + подпись). На мобильном — вертикальный список или 3 в ряд, если помещается; на десктопе — 3 в ряд.
- «Продолжить» disabled до выбора. Смена выбора до подтверждения свободна.

### Экран 3 — стратегия
- Заголовок + ситуация + 2 карточки + напоминание о предмете + «Узнать свою судьбу».
- Визуальная реакция: лёгкое движение тумана (непрерывный slow drift слоёв тумана, усиливается на выбор); на подтверждении — короткий (≤600 мс) сдвиг сцены в сторону выбранного пути (овраг — влево, лес — вправо) и переход к результату. Во время перехода `isTransitioning=true`.

### Экран 4 — результат
- Заголовок «Ты прошёл испытание», дистрикт + символ, предмет, характеристика, короткое объяснение (из таблицы), фраза характеристики.
- **Превью карточки** — это `<img>`, построенный из **того же PNG-blob**, который уйдёт в шаринг/скачивание (гарантия «на экране = на карточке»). Пока карточка готовится — скелетон того же аспекта (нет скачков вёрстки). Появление карточки — финальная анимация (fade/scale ≤400 мс).
- Текст «Своё испытание ты прошёл. Теперь узнай, через что прошёл Хеймитч».
- Кнопки: **«Выбрать сеанс»** (primary), затем «Поделиться результатом», «Скачать карточку», «Пройти ещё раз» (secondary/ghost).
- Ошибки подготовки карточки **не блокируют** «Выбрать сеанс» и просмотр результата.

### «Выбрать сеанс»
- Один и тот же URL (`VITE_TICKETS_URL`) на всех кнопках; ссылка — реальный `<a href target="_blank" rel="noopener">` (открывается новой вкладкой, чтобы не терять сессию). Событие `ticket_cta_click` с `screen: 'draw' | 'result'` отправляется до перехода (`navigator.sendBeacon`/синхронно, без `preventDefault`).

### Футер (минимальный, юридический)
Одна тонкая строка внизу: «12+», название фильма, «Правообладатель/дистрибьютор» — **текст-плейсхолдер, финальные формулировки — от маркетинга/юристов**. Без ссылок на сторонние ресурсы.

## 8. ШАРИНГ ПЕРСОНАЛЬНОЙ КАРТОЧКИ (самый важный раздел)

### 8.1 Проблема и принцип

Частая боль: «текст отлетел от картинки», шрифт не тот, текст уехал/обрезан, картинка пустая, в мессенджере прилетела только ссылка или только текст. Причины — генерация карточки из DOM через `html2canvas` / `html-to-image` / `dom-to-image` (гонки со шрифтами, SVG `foreignObject` в Safari, CORS-taint, зависимость от DPR и CSS) и потеря user-activation при асинхронной генерации внутри обработчика клика.

**Поэтому запрещено:** `html2canvas`, `html-to-image`, `dom-to-image`, скриншот DOM, `foreignObject`, внешние картинки/шрифты с других доменов.

**Принцип:** карточка — **детерминированный растровый рендер на Canvas 2D** по декларативному шаблону в фиксированных координатах. Текст рисуется на canvas вместе с графикой → он физически не может «отлететь». Адрес лендинга и логотип **запечены в сам PNG** → даже если мессенджер выбросит сопроводительный текст, ссылка останется в картинке.

### 8.2 Формат и шаблон

- Размер **1080 × 1920 px** (9:16, stories-friendly), `scale = 1` независимо от `devicePixelRatio`. Экспорт всегда PNG.
- Безопасные зоны: верхние 220 px и нижние 320 px — только фон/декор (UI сторис их перекрывает); ключевой контент в центральной зоне. Поля слева/справа ≥ 72 px.
- Состав (по ТЗ): название фильма «Голодные игры: Рассвет жатвы» (плейсхолдер-вордмарк), номер + символ дистрикта, характеристика, фраза характеристики, выбранный предмет (иконка + название), тематическое оформление (слои фона), логотип КАРО, адрес лендинга (читаемый текст, без `https://`, крупностью ≥ 32 px).
- `card/cardTemplate.ts` — **декларативное описание слоёв** (массив): `{ id, type: 'image' | 'text' | 'rect' | 'gradient', box: {x,y,w,h}, ... }`. Все координаты — в одном месте; при приходе финальных слоёв правится только шаблон и манифест.
- Фон карточки собирается из тех же слоёв-ассетов, что и сцены лендинга (через манифест), плюс акцентный цвет дистрикта.

### 8.3 Движок текста (`card/drawText.ts`)

Собственная функция `drawTextBlock(ctx, { text, box, fontFamily, weight, maxSize, minSize, lineHeight, align, maxLines, color, letterSpacing? })`:
- перенос по словам через `ctx.measureText`;
- **автоподбор размера** шрифта вниз от `maxSize` до `minSize`, пока блок не влезет в `box` (и по ширине, и по числу строк);
- если даже на `minSize` не влезает — многоточие на последней строке + запись в диагностику `overflow: true`;
- центровка/выравнивание по baseline считается явно (`textBaseline = 'alphabetic'`, собственный расчёт), не полагаться на `middle`;
- без эмодзи в тексте карточки; кириллические кавычки «ёлочки» должны присутствовать в шрифте;
- возвращает `{ lines, fontSize, height, overflow }`.

### 8.4 Загрузка ресурсов до рендера (`card/assets.ts`)

Перед **любым** рендером:
1. `await Promise.all(fontsNeeded.map(f => document.fonts.load(f.descriptor, 'АБВГДЕЖЗИЙКЛМНОПРСТУФХЦЧШЩЪЫЬЭЮЯабвгдеёжзийклмнопрстуфхцчшщъыьэюя0123456789«»—')))` + `await document.fonts.ready`. (Проверка именно кириллическим сэмплом, иначе браузер подгрузит только латиницу.)
2. Все изображения: `new Image()`, `img.decoding='async'`, `await img.decode()` (фолбэк на `onload`). Источники — только same-origin или data-URI → canvas никогда не «tainted». Кэш декодированных изображений в `Map`.
3. Если какой-то ассет не загрузился — подставить плейсхолдер-прямоугольник с подписью id ассета (в dev) / нейтральный фон (в prod) и **не падать**.

### 8.5 Предрендер (ключ к рабочему шарингу)

`navigator.share()` требует **transient user activation**; если сначала долго рендерить PNG внутри обработчика клика (особенно Safari/iOS), вызов упадёт с `NotAllowedError`. Поэтому:

- Как только вычислен результат (переход на экран результата), запускается `prepareCard(snapshot)` → `Promise<PreparedCard>`:
  ```ts
  interface PreparedCard {
    key: string;              // `${district}:${item}:${strategy}:${attempt}`
    blob: Blob;               // image/png
    file: File;               // new File([blob], filename, { type: 'image/png', lastModified: Date.now() })
    objectUrl: string;        // для <img> превью и скачивания
    diagnostics: { overflow: boolean; missingAssets: string[]; ms: number };
  }
  ```
- Результат кладётся в `cardCache` (в памяти) по `key`. Предыдущий `objectUrl` вызывает `URL.revokeObjectURL` при повторной попытке/смене результата.
- Рендер идёт через `OffscreenCanvas` если доступен (с `convertToBlob`), иначе `HTMLCanvasElement` + `toBlob` (фолбэк `toDataURL` → blob, если `toBlob` вернул `null`).
- Имя файла: `hunger-games-d{N}-{characteristicSlug}.png` (латиница, без пробелов).
- Кнопки «Поделиться» и «Скачать» **активны только когда карточка готова**. Пока готовится — они в состоянии loading (не disabled-без-объяснения), но не блокируют «Выбрать сеанс».
- Если за 8 с карточка не готова или рендер упал → состояние ошибки: «Не удалось подготовить карточку. Попробуй ещё раз» + кнопка «Повторить» (заново `prepareCard`). Остальной экран работает.
- Рендер строится **только из снапшота актуальных данных** (district, item, strategy → characteristic). Старые решения не используются; кэш инвалидируется по `key`.

### 8.6 «Поделиться результатом» (`card/share.ts`)

Обработчик клика — **синхронный до вызова `navigator.share`**, без `await` перед ним:

```ts
function onShareClick() {
  track('share_click', params());           // не считать публикацией
  const card = cardCache.getReady();        // уже готовый PreparedCard
  if (!card) return showRetry();
  if (shareLock) return; shareLock = true;

  const data = {
    title: 'Голодные игры: Рассвет жатвы',
    text: `${SHARE_TEXT}\n${SITE_URL}`,     // ссылка внутри text, отдельное поле url НЕ передаём вместе с files
    files: [card.file],
  };

  if (navigator.canShare?.({ files: data.files }) && navigator.share) {
    navigator.share(data)
      .catch(err => {
        if (err?.name === 'AbortError') return;          // пользователь закрыл меню — не ошибка, молчим
        openShareFallback();                              // NotAllowedError / DataError / др.
      })
      .finally(() => { shareLock = false; });
  } else {
    shareLock = false;
    openShareFallback();
  }
}
```

Почему так:
- **Файл + текст со ссылкой внутри `text`, без отдельного `url`**: часть приложений при наличии `files` теряет `url` или дублирует его. Ссылка дополнительно запечена в PNG.
- Поддержка проверяется через `canShare({files})` **заранее** (при монтировании экрана результата), чтобы подписи/состояния были корректны и без «мигания» на клике.
- `shareLock` защищает от `InvalidStateError` при повторном тапе, пока меню открыто.
- Ничего не логировать как «опубликовано»: только `share_click`.

### 8.7 Запасной сценарий (когда системный шаринг изображений недоступен или упал)

`ShareSheetFallback` (bottom-sheet) показывает ровно два действия по ТЗ:
1. **«Скачать карточку»** — `download.ts`.
2. **«Скопировать ссылку»** — `clipboard.ts`: `navigator.clipboard.writeText(SITE_URL)`; фолбэк — скрытый `<input>` + `select()` + `document.execCommand('copy')`; фолбэк-2 — показать ссылку в поле с выделением и подсказкой. Результат — `Toast` «Ссылка скопирована».
- Опционально (десктоп, где поддерживается): третья вторичная кнопка «Скопировать картинку» через `navigator.clipboard.write([new ClipboardItem({'image/png': blob})])`, с try/catch — если не поддерживается, скрыта.
- На десктопе без Web Share Level 2 (например, Firefox) кнопка «Поделиться результатом» сразу открывает этот fallback.

### 8.8 «Скачать карточку» (`card/download.ts`)

- Основной путь: `<a href={objectUrl} download={filename}>` + программный клик, затем отложенный `revokeObjectURL` (через ≥ 10 с, не сразу).
- **Встроенные браузеры (Telegram, Instagram, VK, Яндекс.Браузер/in-app WebView) и iOS** иногда игнорируют `download`. Детект: UA-эвристики + проверка `'download' in HTMLAnchorElement.prototype`. Для них — модальное окно с самой картинкой и подсказкой «Нажми и удерживай картинку, чтобы сохранить» (`<img src={objectUrl}>`, `-webkit-touch-callout: default`, `user-select: auto`).
- Событие `card_download` — **только** после успешной подготовки blob и запуска скачивания (не подтверждение сохранения пользователем).
- Если blob не готов — то же сообщение об ошибке и «Повторить».

### 8.9 Ссылка и предпросмотр

- Ссылка в шаринге — на **начало лендинга** (`VITE_SITE_URL`), без индивидуальных параметров результата (по ТЗ индивидуальных страниц и превью нет).
- В `index.html` **статически** (краулеры мессенджеров не исполняют JS) прописать: `og:title`, `og:description` (описание игры), `og:image` (абсолютный URL общей обложки фильма, плейсхолдер 1200×630), `og:url`, `og:type=website`, `og:locale=ru_RU`, `twitter:card=summary_large_image`, `<link rel="canonical">`. Для VK/Telegram — те же OG.
- Скрипт `check-assets.mjs` проверяет, что `og:image` — абсолютный URL и файл существует.

### 8.10 Проверка шаринга (обязательная матрица, записать в `docs/QA.md`)

Вручную/по возможности автоматизированно: iOS Safari (share-sheet → Telegram, WhatsApp, Сообщения, Заметки), Android Chrome (→ Telegram, VK, Viber), in-app браузеры (Telegram, VK, Instagram), Яндекс.Браузер, desktop Chrome/Edge (Web Share есть на Windows), desktop Safari, desktop Firefox (fallback).
Автотесты:
- Юнит: `drawTextBlock` не выходит за `box` на строках разной длины (самая длинная — «Выживальщик», длинные фразы, длинный адрес).
- **Прогон всех 72 комбинаций** (12 дистриктов × 6 сочетаний): `renderCard` возвращает `diagnostics.overflow === false` и `missingAssets` пуст (для плейсхолдеров).
- Playwright (Chromium + WebKit): мок `navigator.share/canShare` → проверка, что вызов происходит **синхронно из клика** и в `files[0]` лежит PNG ровно 1080×1920 (декодировать и проверить размеры); ветка `AbortError` не показывает ошибку; ветка `NotAllowedError` открывает fallback; без `canShare` — fallback.
- Скриншот-регрессия карточек (по 1 на каждую характеристику × 2 дистрикта) — `toHaveScreenshot` с допуском.
- Детерминизм: два рендера одного снапшота дают побайтово одинаковые размеры/хэш пикселей.
- Повторная попытка: после replay карточка строится из новых данных (проверка по тексту характеристики на `diagnostics` или метаданным рендера).

## 9. Ассеты и плейсхолдеры (финальные слои придут позже)

Дистрибьютор передаст послойные макеты с изображениями — состав пока неизвестен. Поэтому:

### 9.1 Манифест `assets/manifest.ts`

```ts
type AssetKind = 'bg-layer' | 'district-symbol' | 'item-icon' | 'strategy-art' | 'logo' | 'wordmark' | 'card-bg' | 'og';
interface AssetEntry {
  id: string;                 // стабильный ключ, на который ссылается код
  kind: AssetKind;
  src: string;                // путь в /public/assets/...
  width: number; height: number;
  status: 'placeholder' | 'final';
  parallax?: { depth: number; driftX?: number; driftY?: number }; // для слоёв сцены
  alt?: string;               // '' для декоративных
}
```

Минимальный набор id (все — плейсхолдеры сейчас):
- Сцены (по 3–5 слоёв с прозрачностью, от дальнего к ближнему): `scene.draw.*`, `scene.item.*`, `scene.strategy.*` (включая `fog.back`, `fog.front`, `path.ravine`, `path.forest`), `scene.result.*`.
- `district.symbol.1` … `district.symbol.12` (квадрат 512×512, прозрачный фон).
- `item.flask`, `item.rope`, `item.medkit` (иконки 256×256).
- `logo.karo` (SVG-плейсхолдер), `wordmark.film` (SVG-плейсхолдер названия фильма текстом), `card.bg.*`, `og.cover` (1200×630).

Код **никогда** не ссылается на файлы напрямую — только `getAsset(id)`. `status: 'placeholder'` в dev-режиме рисует маленький бейдж `PLACEHOLDER: <id>` поверх ассета (скрывается переменной).

### 9.2 Генерация плейсхолдеров

`scripts/gen-placeholders.mjs` создаёт SVG: градиентные «слои» с мягким шумом, полупрозрачные туманные полосы, символ дистрикта как шестиугольник/щит с номером, иконки предметов в простых геометрических формах, фон карточки. Палитра — токены: пепельно-чёрный фон, тёплый «рассветный» акцент (янтарь/медь), приглушённое золото, холодный туман. У каждого дистрикта свой акцентный цвет (12 оттенков, различимые и контрастные с белым текстом; AA для текста на подложке).

### 9.3 Данные 12 дистриктов (`content/districts.ts`)

Характеристики и материалы дистриктов даёт маркетинг. До этого — **временные** короткие подписи по канону книг (пометить `isPlaceholder: true`, вывести TODO-список в `docs/ASSETS.md`):
1 — предметы роскоши · 2 — камнеобработка и оборона · 3 — технологии · 4 — рыболовство · 5 — энергетика · 6 — транспорт · 7 — лесозаготовка · 8 — текстиль · 9 — зерно · 10 — скотоводство · 11 — сельское хозяйство · 12 — угледобыча.
Модель: `{ id: 1..12, title: 'Дистрикт N', tagline: string, accent: '#hex', symbolAssetId: string, isPlaceholder: boolean }`.

### 9.4 Протокол замены на финальные слои (`docs/ASSETS.md`)

1. Положить файлы в `public/assets/final/...` с теми же пропорциями (или обновить `width/height`).
2. В `manifest.ts` сменить `src` и `status: 'final'` для затронутых id.
3. Подправить координаты слоёв в `cardTemplate.ts`, если изменились пропорции.
4. Запустить `npm run check:assets` (все id существуют, размеры совпадают с манифестом, нет битых путей, вес слоя ≤ 300 КБ в webp, общий вес первой загрузки ≤ 1.5 МБ).
5. Запустить прогон 72 карточек — `overflow: false`.
Формат финальных слоёв: WebP/AVIF для фото-слоёв (с PNG-фолбэком там, где нужна alpha в Safari), SVG для символов/иконок/логотипов.

## 10. Аналитика

Адаптер `analytics/analytics.ts`: `track(name, params)`. Реализация по умолчанию: `window.dataLayer.push({ event: name, ...params })` + при `VITE_ANALYTICS_DEBUG` — `console.table`. Подключение конкретной аналитики КАРО (скрипт/счётчик) — **заглушка с TODO**: данные подключения придут от маркетинга. Нужна возможность легко подменить адаптер.

События (имена строго по ТЗ):

| Событие | Когда |
|---|---|
| `landing_view` | Открытие лендинга (один раз на загрузку страницы) |
| `draw_start` | Запуск жеребьёвки |
| `district_assigned` | Присвоение дистрикта |
| `item_selected` | Подтверждение предмета кнопкой «Продолжить» |
| `strategy_selected` | Подтверждение стратегии кнопкой «Узнать свою судьбу» |
| `game_completed` | Первый успешный показ результата в рамках попытки |
| `replay_click` | Нажатие «Пройти ещё раз» |
| `share_click` | Нажатие «Поделиться результатом» |
| `card_download` | Успешная подготовка и запуск скачивания карточки |
| `ticket_cta_click` | Нажатие «Выбрать сеанс», параметр `screen: 'draw' \| 'result'` |

Параметры (все, доступные на момент события): `district`, `item`, `strategy`, `result` (id характеристики), `attempt` (номер попытки в сессии). Для `game_completed` дополнительно `active_time_ms` — время активного прохождения **без** времени, когда вкладка скрыта (`document.visibilityState === 'hidden'`; накопитель в `activeTime.ts` слушает `visibilitychange`, пауза/возобновление, значение персистится при reload).

Дедупликация (`analytics/dedupe.ts`):
- События игровых шагов шлются **только из действий стора** (переход состояния), а не из эффектов рендера → восстановление экрана после reload ничего не шлёт.
- Ключ дедупа `${sessionId}:${attempt}:${eventName}` для `draw_start`, `district_assigned`, `item_selected`, `strategy_selected`, `game_completed`; повторные тапы во время `isTransitioning` / `isDrawing` игнорируются guard-ами.
- `replay_click`, `share_click`, `card_download`, `ticket_cta_click` — каждый реальный клик, но с троттлингом 500 мс против двойных тапов.
- `landing_view` — один раз на загрузку страницы (флаг в памяти модуля, защита от StrictMode-двойного монтирования).
- Юнит-тесты: прогон полного сценария + reload в середине + двойные клики → ожидаемая последовательность событий без дублей.

## 11. Доступность и устойчивость

- Игра понятна и работоспособна без анимаций, без звука, без JS-эффектов (парралакс — только украшение).
- `prefers-reduced-motion`, `prefers-color-scheme` не требуется (тема тёмная фиксированная).
- Фокус-стили видимые, порядок табуляции логичный, `aria-disabled` вместо `disabled` для кнопок с пояснением.
- Не полагаться на цвет: отметка выбора — иконка-галочка + рамка + текстовый `sr-only` «Выбрано».
- Landscape на телефоне: контент прокручивается, кнопки не перекрываются.
- Блокировка двойного тапа: `touch-action: manipulation`, отключить задержку 300 мс.

## 12. Производительность

- LCP ≤ 2.5 с на 4G mid-range; первая загрузка ≤ ~1.5 МБ (без шрифтов — отдельно, subset кириллица+латиница, WOFF2).
- Сцены грузить лениво: следующий экран — `<link rel="preload">`/prefetch во время текущего.
- Слои сцены — `will-change: transform` только на время анимации; не более ~5 анимируемых слоёв одновременно.
- Предрендер карточки не блокирует основной поток надолго: если `OffscreenCanvas` в worker — использовать; иначе `requestIdleCallback`/`setTimeout(0)` между этапами.

## 13. Браузеры

Современные: iOS Safari 16+, Chrome/Edge/Яндекс.Браузер/Samsung Internet (последние 2 версии), Firefox, desktop Safari. Конкретный список «согласованных основных браузеров» уточнит заказчик — заложить именно такой.

## 14. Вне рамок (НЕ делать)

Регистрация/вход, бэкенд, база данных, индивидуальные страницы результатов и индивидуальные OG-превью, таймер, проигрыш, шкалы ресурсов, дополнительные задания, звук, посимвольный набор текста, блоки «О фильме/Актёры/Трейлер», многоязычность, тёмная/светлая тема, синхронизация между устройствами.
